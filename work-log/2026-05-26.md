## Technical Notes

### Router architecture
- ARMv7l, BusyBox v1.36.1, Linux 5.4.213, syslog-ng (not BusyBox syslogd)
- `/etc/` is **tmpfs** (not overlay) — regenerated fresh every boot
- This means rc.d symlink manipulation does NOT survive reboots
- `/data/` is UBIFS (persistent) — used for dashboard files and `.disabled_services`

### Service persistence
- `rm /etc/rc.d/S*svc* ` does NOT survive reboot (tmpfs)
- Firewall includes DO survive (UCI config stored in `/data/`)
- Solution: firewall include runs `/data/dashboard/disable_xiaomi.sh` at boot, which reads `/data/dashboard/.disabled_services` and stops listed services

### API design
- New `action_ps_mem` reads `/proc/*/status` for VmRSS — most reliable memory measurement
- Control characters in `/proc/PID/cmdline` break JSON — must sanitize with `tr` before `json_esc`
- All services use `data` wrapper for frontend consistency (`loadPage` passes `r.data`)

## What failed / Issues
- Initial "Disable Boot" implementation (rc.d symlink removal) doesn't survive reboots on this router — `/etc/` is tmpfs
- `json.DecodeError` on ps_mem endpoint due to control characters in `/proc/*/cmdline` — fixed with `tr` sanitization
- `renderServices` checked `d.code !== 0` but `d` is `r.data` (no `code` field) — fixed to check `d.services`
- `pidof miot` doesn't find the process because `miot` is an init script name, not a binary name

## Session 3 — 2026-05-26 (night)

### VAP config corruption diagnosis
Investigated why "Xi Test" vanished after network cable swap while "Xi Test 2" was fine.

**Root cause 1 — Radio-index ifname "correction"**: `/lib/wifi/qcawificfg80211.sh` checks if VAP ifname's 3rd char matches radio index (wl0X→wifi0, wl1X→wifi1). If mismatched, it overwrites the ifname. But Qualcomm driver uses **inverted naming** (wl01 on wifi1, wl11 on wifi0) due to cached deleted VAP names. Every `wifi reload` fights reality and corrupts ifname assignments.

**Root cause 2 — Variable leakage**: `/lib/wifi/hostapd.sh` `hostapd_set_bss_options()` sets `ssid`, `device`, `phy`, `hwmode` via `config_get` but never declares them `local`. If a `config_get` fails, the previous VAP's value bleeds through. Additionally, line 28 sets a **global** `$ssid` at script-load time.

Both triggered when eth1 flaps (cable swap) and `wifi update`/`wifi reload` fires.

### Fix: Patched Qualcomm wifi scripts via bind-mount
Since `/lib/wifi/` is on read-only squashfs, copied scripts to `/data/dashboard/patched/` and bind-mount over originals:

**hostapd.sh patch**: Added `local ssid device hwmode phy` to `hostapd_set_bss_options()` (line 251).

**qcawificfg80211.sh patch**: Neutered the `config_set "$vif" ifname $vifname` inside the radio-index correction block (replaced with `:`) — preserves the check logic but never overwrites ifnames.

Verified: after `wifi reload` with patched scripts, UCI ifnames survive and hostapd configs have correct SSID + ctrl_interface. Configs no longer cross-contaminate between VAPs.

## Session 5 — 2026-05-26 (post-reboot)

### Xiaomi WPS branding removal

User noticed Mi icon on phone WiFi list after reboot. Root cause: the global Qualcomm hostapd adds WPS Information Elements to beacon frames: `manufacturer=xiaomi`, `device_name=XiaoMiRouter`, `model_name=RD15`. Xiaomi/MIUI phones detect these and show a Mi icon.

apply_vap.sh configs never include WPS fields. The global hostapd does. If the global hostapd takes over user VAP management, Xiaomi branding appears in beacons.

Fix: Added WPS stripping to `check_vaps()` in boot_setup.sh — detects `manufacturer=xiaomi` in config files of user VAPs, re-applies via `apply_vap.sh update` to strip. Runs every 2 min.

Also removed stale duplicate VAPs (wl01, wl03, wl11) that remained after forcing apply_vap.sh update on global-hostapd-managed VAPs.

### Reboot verification

- All 4 VAPs came back up after reboot (Xi Test on wl11/wl01, Xi Test 2.4 on wl13, Xi Test 5G on wl03)
- Zero Xiaomi WPS tags across all user VAP configs
- `extra_wifi` tags survived reboot (/etc/config on persistent sec_cfg ext4)
- Ghost interfaces (wl00, wl02, wl10, wl12 — stale apply_vap.sh ifnames from pre-reboot) cleaned up
- UCI ifnames synced to match actual broadcasting interfaces

### Critical lessons learned

1. **scp with sshpass does NOT work on this router.** Must use HTTP server + wget for file uploads.
2. **Base64 over SSH breaks on large files** (80KB api.cgi overflowed SSH buffer).
3. **deploy.sh sources .env AFTER setting ROUTER_IP default** — .env always wins. Check .env first.
4. **`.env` ROUTER_IP goes stale** — router gets DHCP address that changes. Check `ip neigh` first.
5. **`/etc/config` is on persistent ext4 (sec_cfg)**, NOT tmpfs. UCI wireless config survives reboots.
6. **Global hostapd resets ifnames during boot** — apply_vap.sh ifnames get overwritten. UCI ifnames revert to original values.
7. **Never force apply_vap.sh update on global-hostapd-managed VAPs** — causes duplicate interfaces and config corruption.
8. **Router IP changes**: was 192.168.10.209, now 192.168.10.143 after DHCP.
